# Воспроизведение

## Финальное решение

`scripts/reproduce.py --mode fit` заново обучает Ridge на каждом origin, вычисляет сезонный компонент и запускает Chronos-Bolt по истории до этого origin. Категории, общий фактор и обучающие примеры готовятся после отсечения будущего. Взвешенная Ridge, расширения признаков и фиксированные веса совпадают с исследовательской конфигурацией.

Сначала сохраняется `results/reproduction_protocol.json`. Далее записываются явные компоненты и прогноз ансамбля с равными весами. `final_protocol_intervals.py` строит фиксированные варианты ансамбля, интервалы и таблицы по горизонтам, месяцам, расходам и волатильности. `final_detection_benchmark.py` использует отдельные seed для настройки и проверки порога. `verify.py` сравнивает результаты с неизменяемой копией в `evidence/`.

`--mode cached` пропускает обучение и использует сохранённые компоненты. Это быстрый пересчёт результатов, а не повторное обучение. `--origin` проверяет только один выпуск; интервалы и общий backtest в этом режиме не запускаются.

## Эксперименты и статистика

Код исследовательских расчётов сохранён в `research/scripts/`, параметры — в `configs/`. Для повторения статистического аудита по индивидуальным прогнозам восстановите архивы и выполните:

```bash
python scripts/restore_artifacts.py
python research/scripts/experiment_statistics.py
python research/scripts/interval_statistics.py
python research/scripts/check_statistics.py
python research/scripts/detector_statistics.py
```

Статистика финального детектора также рассчитывается внутри `scripts/final_detection_benchmark.py`: парные различия по независимым пересэмплированным панелям, доверительные интервалы, sign-flip p-value и Holm p-value. Для прогнозов используются общие ключи `(territory_id, origin, date, horizon)` и временные блоки целевых месяцев. Тысячи МО не трактуются как тысячи независимых временных наблюдений. Все сравнения остаются исследовательскими; метрики симуляции относятся к добавленным изменениям на фиксированной реальной истории.

| Эксперимент | Код |
|---|---|
| Базовые и сезонные модели, Ridge | `research/scripts/backtest.py`, `hypothesis_suite.py` |
| Состав ансамбля и общий фактор | `research/scripts/develop_point_ensemble.py` |
| Доли категорий, локальные модели | `research/scripts/architecture_extensions.py` |
| Макро, цены и зарплаты | `research/scripts/combined_sources.py` |
| Календарь, финансовые признаки | `research/scripts/full_calendar_experiments.py`, `prepare_financial_features.py` |
| География, разбиения, синтетика | `research/scripts/generalization_experiments.py` |
| Интервалы | `research/scripts/run_uncertainty.py`, `refine_and_calibrate.py`, `final_protocol_intervals.py` |
| Обнаружение изменений | `research/scripts/detectors_matched.py`, `final_detection_benchmark.py` |
| Кейсы и объяснения | `research/scripts/final_cases_mobility.py`, `final_interval_explanations.py` |
| Горизонты 1, 3, 6, 12 | `research/scripts/contest_horizons.py` |

Исторические расчёты используют сохранённые промежуточные прогнозы, которые поставляются в `artifacts/`. Для повторения дополнительных моделей с новым обучением нужны соответствующие пакеты и веса: полный снимок основного окружения находится в `requirements-environment-lock.txt`, дополнительные окружения — в `environments/`. Основной режим воспроизведения использует `requirements.txt` и только Chronos-Bolt.

Выбор кейсов с временем фиксации до чтения новостей сохранён в `evidence/`. Запуск `final_cases_mobility.py` заново меняет время фиксации и создаёт новый исследовательский результат; для пересборки отчёта используйте сохранённые кейсы.

## Данные и версия окружения

Конкурсная таблица сохранена в исходном виде; готовая полная панель содержит 2 016 МО × 24 месяца × 6 категорий. Внешние данные поставляются как зафиксированные снимки с manifest, URL и принятыми задержками. Исторические даты публикаций не восстановлены: проверка использует наблюдавшийся префикс и исследовательские лаги.

`manifest.json` содержит пути, размеры и SHA-256 поставленных файлов. Веса модели исключены из Git, но скачиваются скриптом по конкретной ревизии. Для побитового сравнения используйте Python 3.11, CPU и зафиксированные версии пакетов. Небольшие различия численных библиотек проверяются с указанными в коде допусками.
